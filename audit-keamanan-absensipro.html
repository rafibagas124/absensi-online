Audit Keamanan AbsensiPro

Ringkasan untuk konsultasi teknis | 23 Agustus 2026

Kesimpulan singkat: project sudah memiliki fondasi SaaS multi-tenant dan beberapa lapisan keamanan, tetapi belum sepenuhnya bebas dari penyimpanan browser. Data utama diarahkan ke Supabase, sedangkan cache, antrean offline, preferensi, rate limit, audit lokal, dan session masih dapat berada di perangkat.

Hal yang Perlu Diperkuat

  1. Pindahkan passwordRequests sepenuhnya ke tabel Supabase.
  2. Jadikan shift_configs Supabase sebagai satu-satunya sumber konfigurasi shift.
  3. Hapus fallback log sensitif dari localStorage atau enkripsi/cache dengan masa berlaku terbatas.
  4. Perketat policy Storage surat dokter berdasarkan company_id dan user/role.
  5. Evaluasi policy publik seperti companies_insert_all, shift_insert_all, dan sec_logs_insert.
  6. Hapus unsafe-eval dari CSP bila semua library sudah mendukung.
  7. Jangan menyimpan service-role key di frontend. Obfuscation Base64/XOR bukan enkripsi.
  8. Pastikan validasi final absensi tetap dilakukan server/database, bukan hanya JavaScript browser.

File Referensi

  • security.js: sanitasi, rate limit, CSRF, audit, Sentry, webhook, backup.
  • supabase_client.js: Supabase Auth dan operasi data.
  • supabase_schema.sql: tabel, RLS, policy, trigger, storage.
  • auth.php dan config.php: autentikasi PHP lama, session, prepared statements, headers.
  • vercel.json: CSP dan security headers deployment.
  • protect.js: anti-iframe dan penghambat shortcut inspect.
  • service-worker.js: cache PWA dan update aset.
